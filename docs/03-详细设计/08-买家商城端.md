## 1. 服务概览

### 1.1 职责与定位

买家商城端是面向 C 端消费者的 Web 应用，覆盖从注册登录、商品浏览、加购、下单、支付到确认收货的完整购物闭环。

| 维度 | 内容 |
|---|---|
| 技术栈 | React 18 + TypeScript 5 + Vite 5 |
| 状态管理 | Zustand |
| 请求库 | Axios |
| 路由 | React Router v6 |
| 样式方案 | Tailwind CSS + CSS Modules（组件级隔离） |
| 构建产物 | 静态文件，由网关在路径 `/` 分发 |
| 设计原则 | 移动端优先响应式；路由懒加载；骨架屏替代 spinner |

### 1.2 上下游依赖

买家端通过 API 网关访问后端，不直接调用任何服务实例。所有接口路径均在 `/api/v1` 下，令牌由请求层统一注入。

| 依赖服务 | 场景 |
|---|---|
| 用户服务 | 注册、登录、令牌刷新、资料与地址管理 |
| 商品目录服务 | 商品列表、搜索、详情、评价 |
| 购物车服务 | 购物车增删改查、结算前校验 |
| 订单服务 | 下单、查询、取消、确认收货、退款申请 |
| 支付服务 | 发起支付、查询支付状态 |

## 3. 请求层与状态管理

### 3.1 Axios 请求封装

所有请求通过单例 `apiClient` 发出，基础配置：`baseURL=/api/v1`、`timeout=10000`、`Content-Type: application/json`。

请求拦截器从 Zustand `authStore` 读取 `access_token` 注入 `Authorization` 头，同时注入 `X-Request-Id`（`crypto.randomUUID()`）。

响应拦截器处理规则：

| 响应情况 | 处理 |
|---|---|
| `code === "OK"` | 返回 `response.data.data` |
| HTTP 401 | 尝试静默刷新（`POST /api/v1/auth/refresh`）；成功则重发原请求一次；失败则清除令牌并跳转 `/login?redirect=<当前路径>` |
| 其他非 2xx | 抛出 `ApiError { code, message }`，由调用方或全局错误边界处理 |

静默刷新期间的并发请求排队等待，不各自触发多次刷新（`Promise` 队列实现）。

### 3.2 全局状态

| Store | 职责 | 持久化 |
|---|---|---|
| `authStore` | `access_token`、`refresh_token`、`user_id`、`nickname`、`roles` | `localStorage`，页面刷新后自动恢复 |
| `cartStore` | 购物车条目数量（Header Badge）；完整购物车数据由页面级请求获取，不全量放 store | 不持久化 |

## 4. 各模块详细设计

### 4.1 账户模块

**注册页 `/register`**

表单字段：账号（邮箱或手机号）、密码、确认密码、验证码。提交后调用 `POST /api/v1/auth/register`，成功后跳转登录页并提示"验证邮件/短信已发送"。密码强度提示实时展示但不阻断输入，提交时校验最低强度。

**登录页 `/login`**

账号密码登录，调用 `POST /api/v1/auth/login`。成功后将令牌写入 `authStore`，跳转 `redirect` 参数指向的路径（无则跳首页）。连续失败 5 次时后端返回锁定错误（`USER-6001`），展示剩余锁定时间倒计时。

**找回密码 `/forgot-password`**

两步流程：第一步输入账号发送验证码（`POST /api/v1/auth/forgot-password`）；第二步输入验证码与新密码（`POST /api/v1/auth/reset-password`）。验证码有效期展示倒计时，过期后可重发（60 秒冷却）。

**个人资料 `/account/profile`**

展示并可编辑昵称、头像（上传至对象存储后提交 URL）、性别、生日。密码修改独立区块，需填当前密码 + 新密码 + 确认。调用 `PUT /api/v1/users/me`。

**收货地址 `/account/addresses`**

地址列表，支持新增、编辑、删除、设为默认。新增/编辑用抽屉（Drawer）表单，收货人、手机号、省市区级联选择、详细地址、邮编。调用 `GET/POST/PUT/DELETE /api/v1/users/me/addresses`。

---

### 4.2 商品模块

**首页 `/`**

分三个区块：顶部分类导航横向滚动（调用 `GET /api/v1/categories`）、banner 静态配置（本期硬编码或由环境变量注入）、热销商品网格（调用 `GET /api/v1/products?sort=sales_desc&page_size=8`）。

骨架屏策略：分类导航与商品网格各有独立骨架，互不阻塞，并发请求。

**分类/列表页 `/categories/:id`**

左侧（桌面）或顶部折叠（移动）为子分类 + 筛选面板（价格区间 slider、标签复选）；主区域商品网格，支持排序切换（综合、销量、价格升/降、上架时间）。URL 参数化筛选状态（`?sort=price_asc&min_price=100&max_price=500&page=2`），可分享/回退。调用 `GET /api/v1/products?category_id=:id&...`。

商品卡片展示：主图、商品名（最多 2 行截断）、价格区间或固定价、标签徽章（新品/热销/促销）。已下架商品不出现在列表中（后端过滤）。

**搜索页 `/search`**

URL 参数 `?q=关键词`。结果布局与列表页相同，增加"搜索词高亮"。无结果时展示空态插图 + "换个关键词试试"引导。调用 `GET /api/v1/products/search?q=...`。

**商品详情页 `/products/:id`**

布局（桌面双列，移动单列）：
- 左列：主图大图 + 缩略图轮播；
- 右列：商品名、评分（星级 + 评价数）、价格、规格选择器（SKU 矩阵，已售罄的规格置灰不可选）、库存提示、数量调节、加入购物车 + 立即购买按钮。
- 下方 Tab：商品详情（富文本）、评价列表（分页）。

SKU 选择逻辑：规格组合不合法（如颜色 × 尺码矩阵中不存在的组合）则对应按钮 disabled，选中完整组合后展示该 SKU 的价格和库存。

商品已下架时展示下架提示卡片，加购与购买按钮不渲染。

调用：`GET /api/v1/products/:id`、`GET /api/v1/products/:id/reviews`。

---

### 4.3 购物车模块 `/cart`

页面分两部分：商品列表（左/主）和价格汇总（右/底部 sticky）。

商品行展示：复选框（单选/全选）、商品图片缩略图、商品名与规格、单价、数量调节器（减/输入/加，最小 1，最大受库存限制）、小计、删除按钮。

失效商品（已下架或无库存）置于列表末尾，样式置灰，标注失效原因，去结算时自动剔除并 toast 提示。

批量操作：全选/取消全选、删除选中。

价格汇总：已选商品件数、商品总价（仅已选）、运费（暂显"免运费"或待结算确认）、合计。"去结算"按钮触发 `POST /api/v1/cart/validate`（结算前校验价格与库存），若有价格变动弹确认弹窗展示差异，用户确认后跳转结算页。

调用：`GET /api/v1/cart`、`POST /api/v1/cart/items`、`PUT /api/v1/cart/items/:id`、`DELETE /api/v1/cart/items/:id`。

Header 徽章数量从 `cartStore` 读取，加购/删除时同步更新。

---

### 4.4 结算与支付模块

**结算页 `/checkout`**

接收来自购物车的选中商品列表（通过路由 state 传递，刷新则重定向回购物车）。

三个区块：
1. 收货地址：展示默认地址，支持切换其他地址（地址列表弹窗）或新增地址（嵌入表单）；
2. 商品清单：只读展示，商品图、名称、规格、单价、数量、小计；
3. 价格明细：商品合计、运费、优惠、应付金额。

提交订单按钮：调用 `POST /api/v1/orders` 并携带幂等键（`Idempotency-Key: crypto.randomUUID()`），按钮点击后立即置灰防重复。成功后跳转 `/checkout/pay/:order_no`。失败（如库存不足 `ORD-5001`）弹错误 Modal 展示缺货明细。

**支付页 `/checkout/pay/:order_no`**

展示订单号、金额、支付截止倒计时（从 `expires_at` 计算，倒计时归零自动显示"订单已超时关闭"并禁用支付）。

渠道选择：Stripe / PayPal 单选卡片。点击"立即支付"调用 `POST /api/v1/payments`，返回 `payment_url` 后在新 tab 打开第三方支付页。

同时轮询 `GET /api/v1/orders/:order_no`（每 3 秒，最多 10 次），支付成功后状态变为 `PAID` 则跳转 `/checkout/result?status=success&order_no=:order_no`，超时仍未变更则提示"支付结果确认中，请稍后查看订单"并跳转订单列表。

**支付结果页 `/checkout/result`**

读取 URL 参数展示成功/失败状态。成功展示订单号与预计送达提示，附"查看订单"与"继续购物"按钮。失败展示原因，附"重试支付"（跳回支付页）与"取消订单"按钮。

### 4.5 订单模块

**订单列表 `/orders`**

顶部状态 Tab：全部、待支付、待发货、已发货、已完成、已取消。URL 参数 `?status=PENDING_PAYMENT`。

订单卡片展示：订单号、下单时间、商品缩略图（最多 3 个）+ 数量标记、实付金额、当前状态、操作按钮（按状态动态渲染）。

待支付订单卡片显示倒计时，归零时 badge 切换为"已关闭"并禁用支付按钮（无需刷新，前端计算）。

分页加载，支持"加载更多"（游标分页）。调用 `GET /api/v1/orders?status=...&cursor=...`。

**订单详情 `/orders/:order_no`**

顶部：状态时间轴（待支付 → 已支付 → 已发货 → 已完成，未到达的步骤置灰）。

中部：收货地址、商品明细表格（商品图/名/规格/单价/数量/小计）、价格汇总。

物流区块：有物流信息时展示承运商与单号，暂不做轨迹查询（本期范围外）。

操作区（按状态显示）：

| 状态 | 可用操作 |
|---|---|
| `PENDING_PAYMENT` | 去支付、取消订单 |
| `PAID` / `PENDING_SHIPMENT` | — |
| `SHIPPED` | 确认收货 |
| `COMPLETED` | 申请退款（调用 `POST /api/v1/orders/:order_no/refund`）、去评价（跳 `/orders/:order_no/review`） |
| `CANCELLED` / `CLOSED` | — |

调用：`GET /api/v1/orders/:order_no`。

**评价页 `/orders/:order_no/review`**

对订单内每个商品独立评分（1–5 星）+ 文字评价（选填，最多 500 字）+ 图片上传（选填，最多 3 张）。提交调用 `POST /api/v1/products/:sku_id/reviews`。已评价过的商品显示评价内容只读。

## 5. 通用组件

| 组件 | 说明 |
|---|---|
| `<AuthGuard>` | 检查 `authStore` 令牌；无令牌重定向 `/login?redirect=<path>` |
| `<PageSkeleton>` | 按页面布局预置骨架，避免布局偏移 |
| `<EmptyState>` | 统一空态插图 + 文字 + 可选操作按钮 |
| `<ErrorBoundary>` | 页面级错误边界，展示"页面出错，请刷新重试"，附 trace_id |
| `<Toast>` | 全局通知，调用 `toast.success/error/info(message)` |
| `<ConfirmDialog>` | 通用二次确认弹窗，接收 title/description/onConfirm |
| `<PriceTag>` | 接收 `cents: number + currency: string`，格式化展示 |
| `<CountdownTimer>` | 接收 `expiresAt: string`，实时倒计时，归零回调 |

## 6. 幂等与防重复提交

- 所有写接口（下单、加购、取消、退款）调用前生成 `Idempotency-Key`（`crypto.randomUUID()`）注入请求头
- 提交类按钮触发后立即设置 `loading=true` 并 disabled，请求完成（成功或失败）后恢复
- 页面级防重：用 `ref` 记录进行中的请求，重复触发时直接返回同一个 Promise

## 7. 错误处理约定

| 错误码 | 用户提示方式 |
|---|---|
| 网络超时 / 5xx | Toast "服务暂时不可用，请稍后重试" |
| `COMMON-1001/1002` | 表单字段级 inline 错误 |
| `COMMON-2001/2002` | 清除令牌，跳转登录页 |
| `COMMON-3001` | Toast "无权限执行此操作" |
| `COMMON-4001` | 渲染 404 页面 |
| `ORD-5001`（库存不足） | Modal 展示缺货商品明细 |
| `CART-6001`（价格变动） | Modal 展示价格差异，用户确认后继续 |

## 8. 构建与部署

| 项 | 内容 |
|---|---|
| 构建命令 | `vite build`，产物输出至 `dist/` |
| 环境变量 | `VITE_API_BASE_URL`（通常为空，走同域网关）、`VITE_APP_ENV` |
| Docker 镜像 | 多阶段构建：`node:20-slim` 构建 → `nginx:alpine` 托管静态文件 |

| 代码分割 | 路由级懒加载（`React.lazy`），公共依赖抽至 vendor chunk |
