## 1. 服务概览

### 1.1 职责与定位

运营管理后台是面向内部角色（商品运营、订单运营、仓储发货、客服、财务、系统管理员）的 Web 应用，提供商品维护、订单处理、发货管理、退款审核、交易对账及系统管理等功能，并按角色动态渲染可见菜单与可用操作。

| 维度 | 内容 |
|---|---|
| 技术栈 | React 18 + TypeScript 5 + Ant Design Pro 6 |
| 状态管理 | Zustand（用户态与权限） |
| 请求库 | Axios（与买家端共享请求层封装逻辑，独立实例） |
| 路由 | React Router v6（嵌套路由，侧边栏由路由树生成） |
| 样式方案 | Ant Design 主题定制 token + CSS Modules |
| 构建产物 | 静态文件，由网关在路径 `/admin` 分发 |
| 设计原则 | 表格/表单密集场景使用 ProTable/ProForm；前端权限仅为体验，真实拦截在后端 |

### 1.2 上下游依赖

| 依赖服务 | 场景 |
|---|---|
| 用户服务 | 登录、令牌刷新、用户与角色管理 |
| 商品目录服务 | 分类、商品、库存管理 |
| 订单服务 | 订单查询、改价、取消、发货、退款审核 |
| 支付服务 | 交易流水查询、对账 |
| 通知服务 | 通知记录查询 |

## 2. 路由与权限矩阵

后台所有路由挂在 `/admin` 前缀下，通过 `<AdminAuthGuard>` 统一校验登录态；各页面在渲染前通过 `usePermission` hook 检查当前用户角色是否在允许列表内，不满足则渲染 403 页。

侧边栏菜单由路由元数据（`meta.roles`）动态过滤生成，不满足角色的菜单项不显示。

| 路径 | 页面 | 可见角色 | 对应需求 |
|---|---|---|---|
| `/admin` | 数据概览看板 | 管理员、商品运营、订单运营、财务 | — |
| `/admin/products/categories` | 分类管理 | 商品运营、管理员 | FR-CAT-001 |
| `/admin/products` | 商品列表 | 商品运营、管理员 | FR-CAT-004~005 |
| `/admin/products/new` | 新建商品 | 商品运营、管理员 | FR-CAT-002 |
| `/admin/products/:id/edit` | 编辑商品 | 商品运营、管理员 | FR-CAT-003 |
| `/admin/inventory` | 库存管理 | 商品运营、管理员 | FR-CAT-009、FR-CAT-012 |
| `/admin/orders` | 订单列表 | 订单运营、仓储、客服、财务、管理员 | FR-ORD-011 |
| `/admin/orders/:order_no` | 订单详情 | 订单运营、客服、管理员 | FR-ORD-011~012 |
| `/admin/orders/shipping` | 发货管理 | 仓储发货、管理员 | FR-ORD-008 |
| `/admin/refunds` | 退款审核 | 订单运营、客服、管理员 | FR-PAY-006 |
| `/admin/finance/transactions` | 交易流水 | 财务、管理员 | FR-PAY-007 |
| `/admin/finance/reconciliation` | 对账管理 | 财务、管理员 | FR-PAY-008 |
| `/admin/system/users` | 用户与账号管理 | 管理员 | FR-US-008~009 |
| `/admin/system/roles` | 角色权限管理 | 管理员 | FR-US-008 |
| `/admin/notifications` | 通知发送记录 | 管理员 | — |

路由元数据结构示例：

```typescript
{ path: '/admin/orders/shipping', meta: { roles: ['WAREHOUSE', 'ADMIN'] } }
```

`usePermission` hook 在页面顶层读取 `authStore.roles` 与 `meta.roles` 取交集，为空则渲染 403 占位页。

## 3. 请求层与权限系统

### 3.1 Axios 请求封装

与买家端共享相同的拦截器逻辑（令牌注入、静默刷新、`ApiError` 抛出），但为独立 axios 实例，`baseURL=/api/v1`。后台接口中部分管理接口路径为 `/api/v1/admin/...`，内部接口（`/internal/v1/...`）不经网关，由 BFF 层或直接服务调用（本期前端不直接调内部接口）。

### 3.2 权限系统

| 层次 | 实现 |
|---|---|
| 路由准入 | `<AdminAuthGuard>` 检查 `authStore` 有令牌；`<RoleGuard roles={[...]}>` 检查角色 |
| 菜单渲染 | 路由树遍历，`meta.roles` 与当前用户角色无交集的菜单项不渲染 |
| 操作按钮 | `usePermission(requiredRoles)` hook 返回 `canAccess: boolean`，不满足则按钮不渲染或 disabled |
| 真实拦截 | 后端按 `X-User-Roles` 校验，前端隐藏仅为体验优化 |

## 4. 各模块详细设计

### 4.1 数据概览看板 `/admin`

四张 KPI 卡片（今日订单量、今日销售额、待处理事项数、待发货订单数），数据通过各服务统计接口聚合（本期各指标各调一次接口，无独立 BFF）。

待处理事项模块：待审退款数、低库存商品数，各附快捷入口。

最近订单列表（最新 10 条，仅展示，点击跳转订单详情）。

---

### 4.2 商品模块

**分类管理 `/admin/products/categories`**

以树形表格（Ant Design `Table` 的嵌套行或专用 Tree 组件）展示分类层级，支持：
- 拖拽排序（同级内，提交 `PUT /api/v1/admin/categories/sort`）
- 新增子分类（行内弹 Modal 表单：名称、排序值）
- 编辑分类名与排序
- 删除（有子分类或商品时后端拒绝，前端展示具体错误）

**商品列表 `/admin/products`**

ProTable，顶部搜索栏支持：商品名关键词、分类、状态（上架/下架/草稿）、时间范围。

每行操作：编辑（跳转编辑页）、上架/下架（`PUT /api/v1/admin/products/:id/status`，操作后行内状态实时更新）、查看详情（新 tab 打开买家端详情页）。

批量操作：勾选多行后可批量上架/下架。

**新建/编辑商品 `/admin/products/new`、`/admin/products/:id/edit`**

使用 ProForm，分步骤或 Tab 布局：

步骤一 — 基本信息：商品标题、分类（树形选择）、品牌、标签（多选）、商品描述（富文本编辑器）、主图上传（最多 1 张）、图集上传（最多 9 张）。

步骤二 — 规格与 SKU：规格名称（如颜色、尺码）和规格值管理；表格形式展示所有 SKU 组合，每行可编辑价格（分，输入展示元）、库存初始值、是否启用。

步骤三 — 发布设置：上架/下架/草稿状态选择。

图片上传至对象存储后得到 URL，保存 URL 字符串至接口。调用 `POST /api/v1/admin/products` 或 `PUT /api/v1/admin/products/:id`。

**库存管理 `/admin/inventory`**

两个 Tab：库存列表和低库存预警。

库存列表：按 SKU 展示可售库存、预占库存、阈值。搜索支持商品名/SKU ID。点击"调整库存"弹 Modal（输入调整量和原因），调用 `POST /api/v1/admin/inventory/:sku_id/adjust`，操作人自动取 `authStore.user_id`。

低库存预警 Tab：仅展示低于阈值的 SKU，默认按库存量升序，附"立即补货"快捷入口跳到对应调整 Modal。

---

### 4.3 订单模块

**订单列表 `/admin/orders`**

ProTable 多条件搜索：订单号精确查询、用户 ID/账号、状态多选、下单时间范围、金额区间。

列：订单号、用户、商品摘要（前两种商品名）、实付金额、状态 badge、下单时间、操作（查看详情）。

支持 CSV 导出（调用 `GET /api/v1/admin/orders/export?...`，后端生成文件后返回下载链接）。

**订单详情 `/admin/orders/:order_no`**

与买家端详情页展示内容相同，增加管理操作区：

| 操作 | 条件 | 接口 |
|---|---|---|
| 改价 | 状态 `PENDING_PAYMENT` | `PUT /api/v1/admin/orders/:order_no/price` |
| 强制取消/关闭 | 状态未完成 | `PUT /api/v1/admin/orders/:order_no/cancel` |
| 添加备注 | 任意状态 | `POST /api/v1/admin/orders/:order_no/remarks` |

改价 Modal：展示原价与新价格输入，需填写改价原因（必填）。

备注区块：按时间倒序展示所有备注（买家备注与客服备注分别标注来源），新增备注 inline 表单。

**发货管理 `/admin/orders/shipping`**

仅展示状态为 `PENDING_SHIPMENT` 的订单，支持按下单时间排序。

每行展示：订单号、买家、商品摘要、收货地址、下单时间。操作：点击"发货"弹 Modal 填写承运商（下拉）和物流单号，调用 `PUT /api/v1/admin/orders/:order_no/ship`。

支持批量发货（CSV 上传：订单号、承运商、物流单号，后端批量处理并返回成功/失败明细）。

---

### 4.4 售后模块 `/admin/refunds`

列表展示退款申请，状态 Tab：待审核、已通过、已驳回、退款中、已退款。

每行：退款单号、关联订单号、申请用户、申请金额、申请原因、申请时间、状态。

点击"审核"跳转详情页：展示订单信息、买家申请原因与凭证图片、申请金额。操作：

- 通过：填写审核备注（选填），调用 `POST /api/v1/admin/refunds/:refund_no/approve`，状态流转至退款中，支付服务处理后异步更新为已退款。
- 驳回：填写驳回原因（必填），调用 `POST /api/v1/admin/refunds/:refund_no/reject`。

---

### 4.5 财务模块

**交易流水 `/admin/finance/transactions`**

ProTable 查询：类型（支付/退款）、渠道（Stripe/PayPal）、状态、时间范围、金额区间。

列：流水号、关联订单/退款单、类型 badge、渠道、金额、状态、第三方流水号、创建时间。

支持 CSV 导出。

**对账管理 `/admin/finance/reconciliation`**

选择日期后点击"拉取账单"（调用 `POST /api/v1/admin/reconciliation`，后端向第三方拉取并比对），对比完成后展示：

- 汇总卡片：已匹配数、差异数、平台多收、平台少收金额。
- 差异明细表：平台流水号、第三方流水号、金额差、差异类型、处理状态。

差异明细支持 CSV 导出，供人工复核。

---

### 4.6 系统管理模块

**用户与账号 `/admin/system/users`**

搜索：账号（邮箱/手机）、昵称、状态、角色。

每行：用户 ID、账号、昵称、角色 Tag 列表、状态（正常/禁用）、注册时间。

操作：编辑角色（多选角色弹 Modal）、禁用/启用（`PUT /api/v1/admin/users/:id/status`）。

**角色权限 `/admin/system/roles`**

展示内置角色（`BUYER`、`PRODUCT_OPS`、`ORDER_OPS`、`WAREHOUSE`、`CS`、`FINANCE`、`ADMIN`）及对应权限说明。本期角色集合固定，不支持自定义权限粒度，管理员只能为账号分配或撤销角色。

**通知记录 `/admin/notifications`**

查询：收件人、渠道、模板、状态、时间范围。支持重新发送失败记录（调用 `POST /api/v1/admin/notifications/:id/retry`）。

## 5. 通用组件

| 组件 | 说明 |
|---|---|
| `<AdminAuthGuard>` | 校验令牌并检查用户包含至少一个后台角色（非 `BUYER`），否则跳 `/admin/login` 或 403 |
| `<RoleGuard roles={[]}>` | 细粒度操作权限包裹，不满足则子节点不渲染 |
| `usePermission(roles)` | hook，返回 `canAccess: boolean`，用于按钮 disabled 控制 |
| `<StatusBadge status={}>` | 统一状态颜色映射（订单/退款/流水各自色系） |
| `<AmountDisplay cents={}>` | 分转元展示，表格中右对齐等宽数字 |
| `<ExportButton>` | 点击触发导出接口，轮询或长连接等待下载链接，完成后自动触发浏览器下载 |

---

## 6. 幂等与防重复提交

与买家端相同策略：写接口注入 `Idempotency-Key`，提交按钮 loading + disabled。批量操作额外在前端做确认弹窗（"将对 N 条订单执行批量发货，是否确认？"）。

## 7. 构建与部署

| 项 | 内容 |
|---|---|
| 构建命令 | `vite build`，产物输出至 `dist/` |
| 环境变量 | `VITE_API_BASE_URL`、`VITE_APP_ENV` |
| Docker 镜像 | 多阶段构建：`node:20-slim` 构建 → `nginx:alpine` 托管静态文件 |
| 网关路由 | Traefik 将 `/admin/api/*` 或 `/api/*` 转发后端，`/admin` 及子路径返回后台 `index.html` |
| 代码分割 | 路由级懒加载，ProTable/ProForm 等 AntD Pro 组件异步导入 |
