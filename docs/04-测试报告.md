### 5.5 网关与鉴权链路

通过 Traefik（`:8080`）验证：

| 场景 | 默认配置（.env.example 占位值） | 正确注入 RSA 密钥后 |
|---|---|---|
| 登录（公开路由） | 200（HS256 签名） | 200（RS256 签名） |
| 受保护 API（带 token） | **401 COMMON-2002** ❌ | 200 ✅ |
| 缺少 token | 401 | 401 ✅ |
| 伪造 `X-User-Roles: ADMIN`（buyer token） | - | 403 COMMON-3001（头被网关覆盖）✅ |
| 真实 ADMIN 调管理接口 | - | 201 ✅ |

- 身份头注入/伪造头剥离防御（`authResponseHeaders` 覆盖机制）验证有效。
- `/internal/*` 无外部路由，内部命名空间不可达。
- **问题**：仓库默认 `.env.example` 提供 `JWT_PUBLIC_KEY=replace-with-jwt-public-key`（非空占位），导致 gateway-auth 走 RS256 校验，而 user-service 在无 `JWT_PRIVATE_KEY` 时降级 HS256，两端算法不匹配，经网关的受保护接口全部 401。直连服务端口（seed/E2E/smoke 所用）不受影响，掩盖了该问题（见 F1）。

## 7. 发现的问题

### P1（高）

- **F1 网关鉴权默认配置失效**：`.env.example` 的 `JWT_PUBLIC_KEY` 占位值使 gateway-auth 强制 RS256，与 user-service 的开发降级 HS256 不匹配，经网关的受保护 API 全部 401。本地开发修复：`.env` 中清空 `JWT_PUBLIC_KEY`（触发双端 HS256 降级），或运行 `backend/scripts/generate_secrets.py` 后将生成的 PEM 注入 `.env` 的 `JWT_PRIVATE_KEY`/`JWT_PUBLIC_KEY` 并重启 user-service/gateway-auth。注意 `generate_secrets.py` 目前只写 `infra/keys/` 与轮换 `INTERNAL_TOKEN`，**不会**自动更新 `.env` 的 JWT 键，建议脚本补写或文档显式说明。已在报告生成前用临时 RSA 密钥验证修复后全链路通过，并已恢复原始配置。

### P2（中）

- **F2 `smoke_order.py` 使用硬编码 SKU**：脚本写死 sku_id `3001`/`3002`，种子数据为雪花 ID，直接运行必然 ORD-7002 失败；用真实 SKU 验证逻辑全部通过。建议脚本动态创建/查询商品后取真实 SKU。
- **F3 `smoke_payment.py` 非幂等**：固定 `order_no=SO_TEST_PAY` 与 `third_party_payment_id=pi_123`，重复运行触发 `uk_tx_third_party`/`uk_payments_third_party` 唯一约束冲突；清理旧数据后全流程通过（含幂等重放 replay=True）。建议每次运行使用时间戳后缀。

### P3（低）

- **F4 `smoke_cart.py` 端口与仓库配置不一致**：脚本硬编码 `redis://localhost:6380/15`，而 `.env`/`.env.example` 为 `REDIS_PORT=6379`（Compose 默认是 6380），按仓库配置直接运行连接失败；改用 6379 后逻辑通过。
- **F5 `smoke_catalog.py` 超卖场景无效**：两次预占复用同一 `order_no`（SO_TEST_0001），第二次实际命中幂等重放而非超卖拒绝；超卖保护路径由 `e2e_checkout.py` 覆盖（ORD-5001），但该 smoke 断言名不符实。
- **F6 smoke 脚本运行前置条件无文档**：需在服务目录 + 环境变量，从 `backend/` 直接运行会 import 到 user-service；README/AGENTS 未说明，首次使用者会误判为脚本损坏。

### P4（信息）

- **F7 前端构建告警**：admin antd chunk 约 905 KB（建议按需引入/code-split）；`pages.tsx` 同时静态/动态导入，动态加载未生效。
- **F8 测试资产规模与策略差距**：单测 27 个、无覆盖率配置、无 testcontainers 集成/契约/并发/混沌测试；前端 `test` 脚本为占位输出。
- **F9 `ruff format` 未纳入 CI**：`ruff check` 全绿，但 format 检查有 116 个文件待格式化（CI 仅执行 check，不算回归）。
- **F10 Consul 无业务服务注册**：验证确认 `consul` 中无任何业务服务（与 DEBT-020 一致）。

### 本次已修复

- `backend/services/order-service/tests/unit/test_order.py`：`ruff check --fix` 修正 import 排序与无用 `noqa`（2 处），`ruff check .` 恢复全绿，该服务单测重跑 5/5 通过。

## 8. 结论与建议

1. **核心业务链路健康**：下单结账 Saga、库存预占/释放、支付幂等、outbox 事件派发、网关身份注入与伪造头剥离均可正常工作。
2. **优先修复 F1**：网关鉴权是需求 FR-PLT-002 的强制项，默认配置下失效会阻塞所有经网关的登录后功能；建议修正 `.env.example` 占位值处理或让 `generate_secrets.py` 自动写入 `.env`。
3. **统一 smoke 脚本治理（F2~F6）**：改为动态数据/参数化端口并补充运行说明，使其可重复执行，纳入 CI 或独立脚本任务。
4. **补齐测试策略缺口（F8）**：按 `07-平台与部署.md` §10 增加覆盖率门禁（pytest-cov）、testcontainers 集成测试与前端测试框架，当前 27 个单测不足以支撑质量门禁。
5. **跟进已登记债务**：订单超时关闭（DEBT-001）、下单幂等兜底（DEBT-002）、支付金额强校验（DEBT-003）等 P1 债务应优先实现并纳入回归。
